# CR 审核清单（AI 判据部分）

> 与 `templates/CR-代码审查记录.md` §0 硬规则表同源（改动任一侧须同步另一侧）。
> 本清单用于 MR 自动审核；§0 逐条核表仍由会话内 code-reviewer 与人审填写。
> 风格问题（命名、格式、注释多少）一律不报——那是 linter 的职权。

| 编号 | 判据 | 严重级 |
|---|---|---|
| CR-A1 | 空指针/越界/资源未关闭这类**会真出错**的缺陷路径 | 🔴 |
| CR-A2 | 错误被吞（catch 后不抛不记、失败返回值被忽略），且改变了可见行为 | 🔴 |
| CR-A3 | 与提供的变更上下文自相矛盾（如断言了 A 又依赖非 A） | 🔴 |
| CR-A4 | 并发/事务边界处理不一致（同类操作一处加锁一处不加） | 🟡 |
| CR-A5 | 缺测试的关键分支：改了行为但新路径无断言覆盖 | 🟡 |
| CR-A6 | 契约破坏：函数签名/返回结构变化但调用点未见同步 | 🔴 |

## 判不了就别说
- 性能"可能有问题"没有证据支撑 —— 不报；有明确复杂度/循环证据才报。
- 安全问题只报**利用路径明确**的（拼接 SQL、命令注入），不报泛泛"建议加固"。
- 看不到的文件不猜：只判打包上下文里出现的代码。

## 输出
按输出协议只回一个 JSON。`rule` 字段填上表编号（如 CR-A1）。同一问题只报一次，不换着说法重复。
