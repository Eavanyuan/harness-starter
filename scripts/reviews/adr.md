# ADR 审核清单（AI 判据部分）

> 机器判据（commit hash / 路径引用存在性）已由脚本先跑过，**不要重复报**。
> 你只判决策质量，不判决策本身对不对（那是 Tech Lead 的批红职权）。

| 编号 | 判据 | 严重级 |
|---|---|---|
| ADR-A1 | 没有候选对比，或候选只有"目标方案"和一个稻草人（明显凑数的反例） | 🔴 |
| ADR-A2 | 选型理由引用了不存在的约束（与提供的上下文矛盾） | 🔴 |
| ADR-A3 | 决策的代价/风险一节缺失，或风险与所选方案明显无关（复制粘贴痕迹） | 🟡 |
| ADR-A4 | 结论与理由脱节：理由支持 A 结论选了 B | 🔴 |
| ADR-A5 | 未写"何时 revisit"（什么信号出现时该重新裁决） | 🟡 |

## 判不了就别说
- 技术选型"到底哪个更好" —— 只核论证过程自洽，不替人做选型。
- 与其他 ADR 的深层架构冲突需要全库视野 —— 只报上下文里能直接看出的。

## 输出
按输出协议只回一个 JSON。`rule` 字段填上表编号（如 ADR-A1）。
