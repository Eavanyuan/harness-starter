# RS 审核清单（AI 判据部分）

> 机器判据（必填章节、验收标准格式）已由脚本先跑过，**不要重复报**这些。
> 你只判机器判不了的三件事：需求说得清、边界想得到、和现状不打架。

| 编号 | 判据 | 严重级 |
|---|---|---|
| RS-A1 | 每条核心需求可定位到至少一个用户故事；没有"孤儿需求" | 🔴 |
| RS-A2 | 验收标准的 Given/When/Then 中 Then 是**可观测**结果（能验证通过/不通过），不是"正常""正确"这类无法判定的词 | 🔴 |
| RS-A3 | 需求之间互相矛盾、或与「范围外」冲突 | 🔴 |
| RS-A4 | 明显缺失的边界/异常场景（空输入、并发、失败回滚、权限）只报**该需求会真出错**的，不报想象出来的 | 🟡 |
| RS-A5 | 开放问题里已有结论但没挪进需求正文（账实分离） | 🟡 |
| RS-A6 | 术语表与正文用词不一致（同一概念两个叫法） | 🟡 |

## 判不了就别说
- 业务优先级对不对、商业价值高不高 —— PM 的职权，不在审核范围。
- "建议再加一个功能" —— 不是审核，是设计越权，不报。

## 输出
按输出协议只回一个 JSON。`rule` 字段填上表编号（如 RS-A2）。severity 按表；拿不准一律 yellow。
