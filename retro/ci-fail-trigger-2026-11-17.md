# Retro — ci-fail-trigger（2026-11-17）

## 一句话

把"我提的 PR CI 红"从盲区变成第三触发形态：认领→拉日志→归因（引入 vs 基线同款）→失败工单；三轮 CR 把两个"静默不修"的窄角全部堵死。

## 教训

1. **"空结果"永远有两种成因**：没识别出来 ≠ 没有问题。提取为空（trace 拉不到/栈不认识）曾直落 inherited_only"不修"——CR 一审 🔴#1。设计任何分类器时先问：空类是"真空"还是"没看见"？
2. **半盲视角同样不可判"没有"**：可见部分恰好全继承 + 部分 trace 失败，仍会误判"不修"——二审 🔴#1′。与 task-loop-close 的"视角≠事实"同一条根：判"无"的前提是视角完整，否则降级 opaque（人看）而非下结论。
3. **在场判据不许挂在会被吞错的调用上**：详情拉取用 optional 吞错，瞬断会让"本轮看不见"伪装"触发消失"→ sweep 误关账——二审 🔴#2。凡是被 sweep/对账消费的信号，取它的调用必须 fail loud。
4. **真实日志先于正则**：六栈识别器的形态全部来自 !1896 实测（runner 时间戳前缀、同文件跨 job 绝对路径不同、两 job 同因编译错）；列表接口不带 head_pipeline 也是实测——纸面 API 文档会说"有这个字段"。
5. **不认识的形态要安全降级而不是硬猜**：Gradle 零识别 → opaque 工单（打开 job 链接人工定位），不误判不丢弃。

## 残留（KI）

- 基线取目标分支最新流水（非 merge-base 点）——晚于 MR 基点的新红会把真引入误判继承（漏修方向，新流水重评兜底）
- failedJobs=0 且 jobs 翻页截断的窄角（需 ≥100 个比失败 job 更新的 job 才触达，GitLab jobs 按 id 降序）——一行条件可闭合，留下批
- Gradle 原生格式（> Task :x FAILED）未识别——现走 opaque，真实高频出现时加正则
