## 值得留下的经验

1. **规则不要跑在原始拼写上**。续行 `git push \`⏎--force`、词内转义 `pu\sh`、
   commit message 里的示例命令——三类问题（漏拦 + 误拦）一个根因：判定文本 ≠ 执行语义。
   ruleView（续行归一 + 引号遮蔽 + token 重建）之后，正则与 token 判定共用同一视图。
2. **豁免出口与拦截同批交付**。scan-ok: <≥8字理由> 与引号遮蔽一起上——只修误拦不给出口，
   第一次被拦的文档作者就会去关整个门禁（checklist 的老教训）。
3. **前缀描述字面命令，不描述替换结果**。allowlist 前缀 + `$( )` = 把未判内容包进豁免，
   一条判据（段内含未引号命令替换即不豁免前缀）堵死。
4. **测试脚本自身的 JSON 构造 bug 会制造假阳性**：payload 截断 → "无法解析" 也 exit 2，
   负向用例全绿。要害是 C 节那组手写 payload 的**正向对照**——没有放行用例的拦截测试
   等于自证清白。这条已作为 gate-regressions.test.sh 的结构写死（负向+正向成对）。
5. **`npm run -s` 会注入 loglevel=silent**，吞掉 npm pack 的 notice 清单——本地红、CI 绿，
   两边不同答案（Y4）。断言 npm 输出时用 `--json`（stdout 数据通道，不受 loglevel 影响）。

## 并发协作的教训（本轮实际发生）

两个会话（DeepSeek 僵尸判据批与本批）在同一工作树上并发写入，验证证据一度被
中间态污染（gate 红了 15 分钟，干净 worktree 复核才确认是混流）。
本轮处置：按文件集隔离提交（staleTaskDays 键用暂存区摘出留在工作树），
共享文件（package.json / test）等对方静默后再动。**建议**：同仓多会话要么分工到
不相交文件集，要么串行——"冻结-提交-解冻"比 race 更便宜。
