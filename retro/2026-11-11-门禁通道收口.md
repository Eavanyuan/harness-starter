# 门禁通道收口（2026-11-11）

> 起因：全仓架构审核（`.ai/review/architecture-review.md`）指出两处**通道性绕过**——
> 不是规则不够多，而是有两条路根本不经过规则。
> 任务账本：`.ai/tasks/gate-channel-fix/state.json`（S 档 bugfix，红灯日志 `GC-RED.log` 20 条红）。

## 绕过是什么样

| 缺口 | 复现 | 为什么没被现有判据拦住 |
|---|---|---|
| Bash 写 state | `echo '{...}' > .ai/tasks/x/state.json` | `WRITE_TOOLS` 不含 Bash；`guard_state` 挂在 Write/Edit 上 |
| Bash 写受保护区 | `echo x > hooks/guard_command.mjs` | 同上——`protected` 只对 Write 生效 |
| Bash 读凭据 | `cat .env` | `sensitiveRead` 只挂 Read 工具 |
| allowlist 短路 | `mvn test; git push --force`（allowlist 有 `mvn test`） | 命中前缀直接 `exit 0`，后面的规则一条没跑 |

四条的共同点：**判据本身是对的，只是有条路不经过它**。这类缺口最难在评审里看见，
因为读代码时每一条规则都写得很严谨。

## 改了什么

1. **两条通道共用一套路径判据**（`hooks/lib/path_guards.mjs`）：
   Write/Edit 与 Bash 的写目标走同一个分类函数，顺序（示例文件先于敏感）只在一个地方能改错。
2. **shell 词法只回答两个问题**（`hooks/lib/shell.mjs`）：往哪写、从哪读。
   覆盖 `>` `>>` `tee` `cp` `mv` `sed -i` `dd` `truncate`；`bash -c` / `eval` 递归一层。
   宁可判"读/写"也不漏判，但只有像路径的词才参与敏感判定——`grep credentials src/`
   与 `grep "\.env" README.md` 必须放行，否则误拦会把门禁逼成噪音。
3. **state 与证据目录一律不许 shell 写**：前者绕开证据校验，后者等于手写日志。
   这两条不是"多加一条规则"，是让**唯一合法路径**成为唯一路径。
4. **allowlist 改段级**：先切段再判规则，前缀只豁免它命中的那一段，且不豁免路径判据、
   不豁免"管道送进解释器"（前缀描述一条命令，不描述管道）。
5. **glob 四份实现收敛成一份**（`hooks/lib/glob.mjs`），并加结构断言：除它之外不许再有
   `function globTo…`。四份里只有一份支持 `{a,b}`，`a/**/b` 对 `a/b` 的判定还相反。
6. **证据口径补两个口子**：`verify-run.sh` 的 todo-id 加白名单（`../x` 能把日志写出
   `.ai/verify`，而写到别处的日志没有任何判据看得见）；`gates.extraSourceGlobs` 把
   `hooks/ scripts/ templates/` 纳入本仓自身的新鲜度口径——dogfood 时改门禁却不用重跑证据，
   是这套东西最讽刺的一个缺口。

## 仍然没解决的（这一轮刻意不做）

| 项 | 现状 | 为什么先不动 |
|---|---|---|
| 僵尸任务无机器判据 | doctor 只提醒两条停在 impl 9–10 天的任务 | 要动就得同时定"谁来 abandon"。CI 直接判红会让仓库长期红着，等于训练人忽略红灯 |
| retro 不闭合 | 8 个 done，`retro/` 3 份 | 判据要先定目录与命名（两种风格并存），属于约定问题不是代码问题 |
| S 档仍过重 | 5 文件 bugfix 走满 9 阶段 | 合并 ci/retro 会改变阶段链与既有 state 的合法性，得单独设计迁移 |
| `harness-cli.mjs` 1852 行 | 单点最重 | 拆分是纯重构，风险与收益都要单独一轮 |
| 证据可跨任务挪用 | 日志不绑 commit | 加 `# commit:` 头会让全部历史日志失效；先堵住"手写日志"这条最便宜的路 |

**"防失误不防故意"仍然成立**：`bash -c` 之外还有 `node -e`、变量拼路径、直接改 git 历史。
门禁的作用是让绕过需要刻意为之，而不是顺手就能走；真正的防线是 CR 与人审。

## 一条教训

判据写得越严谨，越容易忘记问"它挂在哪个事件上"。这次四条缺口没有一条是规则写错，
全部是**挂载点漏了**。以后加判据时先问：这条规则对"所有能产生该效果的动作"都生效吗？
