# Retro — task-loop-close（2026-11-16）

## 一句话

两次真实运行证明前半环可靠后，本批把"关账半环 + 运行品质"补上；一审抓出的 🔴（sweep 把"不在本轮触发集"当"触发消失"）是本批最值钱的一课。

## 教训

1. **"视角 ≠ 事实"是 sweep 类设计的通病**：触发列表是"本轮我看见了什么"，不是"世界是什么"。软失败、`--mr` 过滤、`--profile b`、翻页截断（KI-3）都会收窄视角——任何"列表里没有 = 消失"的判定，都必须先证明"本轮视角是完整的"。一审实测复现（健康认领 → 断连一轮 → 误关账）正是动机事故自己的形态：**修 bug 的代码差点复刻 bug 的伤害路径**。
2. **观测三件套缺一不可**：die 双通道（stdout 同步）、轮次围栏行、wrapper 2>&1。plist 把 stderr 分流到 .err 后，".out 只见凭据已载入"与"正常跳过"不可区分——9 小时无人发现。任何"报错只走 stderr"的守护进程都要问一句：日志聚合面能看到它吗？
3. **旧格式迁移选"重认领重建"而非"补写字段"**：无基准可比对时，补写等于把"可能已过期的 pending 清单"合法化；重建虽然多一次认领动作，但换来清单与事实一致（live ack-1882 直接受益）。
4. **CR 自举顺序**：CLOSE-GATE 日志要在 todo 写入 state **之前**生成（gate 运行时 ci-verify 会找 todo 引用的日志，而日志是 gate 跑完才落盘）——mr-verb-trigger 已总结过，本批照做一次过。
