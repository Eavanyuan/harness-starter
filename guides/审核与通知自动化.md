# 审核与通知自动化接入指南

> 对应需求：`docs/01-requirements/RS-审核与通知自动化.md`。
> 三件东西：`harness.rules.json`（路由规则）＋ `scripts/review-router.mjs` / `scripts/ai-review.mjs`（审核自动化）＋ `scripts/lib/notify.mjs` / `scripts/harness-broker.mjs`（通知自动化）。
> 设计原则：机器能判的不用 AI；AI 是票拟，批红归角色；一切失败 fail-closed，绝不静默放行。

## 一、审核自动化：MR 触发 → 自动路由 → 审核 → 🔴 挡合入

`.gitlab-ci.yml` 接线样例（按类型分 job，`rules:changes` 防无关 push 重跑烧 token）：

```yaml
review:route:
  rules: [{ if: '$CI_PIPELINE_SOURCE == "merge_request_event"' }]
  script: node scripts/review-router.mjs --base "origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME"

review:rs:
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
      changes: ["docs/01-requirements/**", ".ai/tasks/*/rs.md"]
  script: node scripts/ai-review.mjs --type rs --base "origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME"

review:cr:
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
      changes: ["backend/**", "frontend/src/**"]   # 与 harness.rules.json 的 cr 路径保持一致
  script: node scripts/ai-review.mjs --type cr --base "origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME"
```

退出码即门禁：`0` 通过；`1` 有 🔴（pipeline 红 → GitLab 合入规则挡住）；`2` 基础设施失败（同样红，绝不放行）。审核结论双落账：`.ai/reviews/<type>-<commit>.md`（入库，CI 可对账）＋ MR 嵌线（人读）。

### 必配 env（CI/CD 变量，masked）

| 变量 | 作用 |
|---|---|
| `AI_REVIEW_BASE_URL` | OpenAI 兼容端点（GLM/OpenAI/DeepSeek/自建网关均可） |
| `AI_REVIEW_API_KEY` | 模型凭据（只给审核用，不给 push 权） |
| `AI_REVIEW_MODEL` | 缺省模型；`harness.rules.json` 的 `model_tiers.narrow/deep` 可分档覆盖 |

### 省 token 的五个已内置机制

1. **L0 机器判据零 token**：RS 缺章节、无 Given/When/Then、ADR 引用不存在的 commit/路径——脚本先判，🔴 直接出，模型都不用调。
2. **L1 预打包**：清单前缀（静态，吃 API prompt cache）＋变更文件硬顶（`bundle.max_files=12`、`max_lines_per_file=600`，超限截断并在结论注明）。
3. **增量缓存**：同文件未变更沿用上轮结论，不重复调模型（`.ai/reviews/.cache-<type>.json`）。
4. **输出封顶**：findings 上限 `max_findings`，红优先保留。
5. **计量落账**：每次运行的 token 用量进 `.ai/ledger/events.jsonl`（`ledger:report` 可复盘哪类审核最烧钱）。

## 二、通知自动化：broker（票拟找人）

broker 是**薄事件桥**：不写 state、不跑 agent、不合 MR；一切落账走 GitLab 文件 API 的正式提交。

```bash
# HOST 默认 127.0.0.1：只绑回环，外部 webhook 打不进来。要接回调必须显式设 0.0.0.0。
# FEISHU_VERIFY_TOKEN 是飞书应用的 Verification Token，缺它则决策回投直接 503（见「安全边界」）。
HOST=0.0.0.0 \
GITLAB_WEBHOOK_SECRET=xxx GITLAB_URL=https://gitlab.example.com GITLAB_TOKEN=bot-token \
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxx \
FEISHU_VERIFY_TOKEN=xxx \
FEISHU_NAME_MAP='{"ou_xxx":"张三"}' GITLAB_DEFAULT_BRANCH=main \
node scripts/harness-broker.mjs --port 8788
```

GitLab 侧：项目 → Webhooks → 填 `http://<host>:8788/webhook/gitlab`，secret 同上，勾 Merge request + Pipeline 事件。
飞书侧：卡片回调地址配 `http://<host>:8788/webhook/feishu`。登记地址时飞书会先打一次
`url_verification`，broker 会把 `challenge` 原样回显——不回显的话地址根本配不上。

### 事件流

| 事件 | 行为 |
|---|---|
| MR open/reopen | 拉 diffs → 按 rules 路由 → 卡片列出命中的审核与**批红角色** |
| diffs 接口失败 | 通知降级送达（fail-open，卡片注明），审核本体不受影响 |
| pipeline failed | 卡片找**作者**（不刷全员） |
| 其他事件 | 只进 digest 日志，不推卡片（防通知疲劳） |
| 决策卡片点选 | 以批红人身份把结论写进 RS「开放问题」表（GitLab 提交，commit message 带身份）；账实不符（OP 行不存在）显式 422，不盲写 |

### 安全边界

- **两个入口两套鉴权，都不能省**：GitLab 侧 `x-gitlab-token`（不匹配 403）；飞书侧 `body.token`
  对比 `FEISHU_VERIFY_TOKEN`（不匹配 403，**未配置则 503 拒服务**）。
  读路径可以试点裸奔，写路径不行：回投是唯一会改仓库的动作，而 `operator.open_id` 是调用方给的，
  不验签就等于允许任何人以任意人的名义批红。
- bot token 只需 `api` 读 + 文件写权限；**不给**合 MR、不给 push 保护分支。
- 决策回投只改 RS 文档的 OP 行；state.json 一律不碰（OP-1 的正式方案见 RS 开放问题表）。
- `HOST` 非回环且两个 token 没配齐时，启动日志会显式告警——绑 0.0.0.0 而不配 token
  等于把回投入口挂到公网。

## 三、调整路由 = 改数据不改代码

所有路径模式、判据、模型档、批红角色都在 `harness.rules.json`：新仓库改 `reviews.cr.paths_from` 的 projects 槽（`harness.config.json`）；新增审核类型加一段 `reviews.<id>`，`machine_checks[].id` 必须命中 `scripts/lib/review-checks.mjs` 注册表（未知 id 直接 exit 2，不静默跳过）。

## 四、常见问题

- **本地试跑不烧钱**：`node scripts/ai-review.mjs --type rs --dry-run ...` 打印打包统计，0 次 API 调用。
- **没配模型 key**：机器判据有 🔴 仍会阻断（exit 1）；判据干净则 exit 2——缺凭据得不出结论，拒绝装作通过。
- **`--machine-only`**：只跑 L0 判据的显式降级（例如内网审核禁用外部模型时）。
  **配了 key 也不调模型**——它的全部意义就是"这次不花钱"，所以判断顺序排在"有没有凭据"之前。
  同理，机器判据已经出 🔴 时也不再调模型：AI 再多说什么都改不了退出码，只多一笔 token。
- **换机器/换包之后先验一遍装出来能不能用**：`harness.rules.json` 是审核自动化的唯一数据源，
  它必须随包发布（`package.json` 的 `files`）。init 现在对"声明了但包里没有"的模板文件直接报错，
  不再静默跳过——以前的表现是 install 绿灯、第一次跑 router 才 exit 2。
