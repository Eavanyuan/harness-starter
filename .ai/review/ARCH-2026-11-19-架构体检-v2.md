## §1 新引入/修复暴露的问题（本批代码自身）

### 必须修（2 条）

**1.【正确性】blocked 网络失败轮被记为"成功轮"，健康告警对 claims 单点断网失明且反复清零**
- 位置：scripts/task-loop.mjs:597、:888（`finish({ ..., stamp: !softFail.length })`）与 :211-217（finish→`markHealth(!!stamp)`）。
- 问题：claim_error / release_failed（claims 远端不可达——正是上次 D1 的场景）→ `blocked++`，但 `stamp` 只看 softFail。softFail 为空（gitlab 正常）时 stamp=true → markHealth(true) → streak 清零、lastSuccessAt 刷新。
- 实测（本机临时仓）：gitlab mock 正常+活跃 CI 触发，删 claims 远端后连跑两轮：两轮均 exit 1、`claim_error` 落账，但 health.json 两轮后仍是 `{"noSuccessStreak":0}`。
- 影响：claims 断网期间每轮 exit 1，loop_degraded 永不触发、健康永远绿——P0-1 与 P0-3 组合后，D1+D2 两个最核心场景的交集反而无告警（launchd/systemd 对 exit 1 不通知；ledger 有事件但无消费端告警）。
- 修复方向：网络类 blocked（claim_error/release_failed）计入无成功轮（如 stamp 改 `!softFail.length && !netBlocked`，或 finish 前 markHealth(false)）。注意与 zombie/budget_exhausted 等**业务** blocked 区分——升级给人属正常流转，不该每小时告警一次。

**2.【流程约束】P3 批次两件交付无 CR 记录，违反规则 8**
- 位置：`.ai/tasks/p3-verify-rotation/state.json`（review 阶段 gate=pass、agent="self-review"、artifacts 为空对象）；`.ai/tasks/hostless-env-notes/state.json`（review gate=pass、note="close 收尾（套件见 CLOSE-GATE 日志）"）；`.ai/review/` 下无对应 CR 文件。对照：p0/p1/p2 均有 `CR-2026-11-19-*.md`（p0 CR 含完整 §0 硬规则表，且诚实记录了 H9 的 🔴 部分）。
- 依据：AGENTS.md 规则 8："S 档……必须走 rs……和 cr（按 CR 模板 + §0）。跳 cr 等于交付未审代码。"
- 影响：本批验收对象中 P3 两件未经独立审（本报告已代为补审 verify-rotate.mjs 与 close 注释，未发现代码级问题）；更重要的是**跳 cr 目前无机器判据**——review gate 填 pass 即可通过，规则 8 的执行全靠自觉。
- 修复方向：补两份 CR 记录（按模板+§0）；在 checkStageExit 或 close 流程加判据：S_FOLD_FROM 后创建的任务 review 阶段 gate=pass 但 artifacts 无 review 声明且无豁免记名 → 判红（与 retro 落盘判据同构）。

### 值得考虑（3 条）

**3. 身份检查 `meta.task` 为空时 pathspec 退化为整个 `.ai/tasks/`**（hooks/lib/verify.mjs:1003-1005）
实测：本人提交的合规任务，仅因 `meta.task` 为空 + 此后**别处**一条 zwork 提交触碰其他任务目录，即被误拦（`git log -1 -- .ai/tasks/` 命中他人提交）。建议：meta.task 缺失/非字符串时跳过身份判定（fail-open，与该检查其余 catch 口径一致）。

**4. retro/阶段豁免的 waived_by 语义漂移：记理由不记人**（p3 state：adr/fs_review/wbs/retro 四站 waived_by 全是"S 档：……"理由文本）
ci-verify 只查非空（:206-210），签字追溯链退化为理由陈述。建议：约定 waived_by 填人名（理由放 note），或在判据里提示"waived_by 应为记名"。

**5. close 工作流文档不可达**（见 §0 P3-2）——6 步工作流是给使用者看的，落在 close.mjs:158-169 注释里等于没发布。挪/抄进 guides/（或 README 的 close 段），close 命令输出里也可指路。

## §2 遗留/新可见问题（上次未列或修复后新显影）

### 值得考虑

**1. healthAlertTicks 口径错：默认首警延迟 5 小时，两处文案写"≈30 分钟"**
代码注释（task-loop.mjs:179"默认 10 拍 ≈ 30 分钟心跳"）与 harness.rules.json `$comment3`（"默认 10≈30 分钟"）都错：真实节拍 pollSeconds=1800s（同文件 `$comment`），10 拍=**300 分钟**。D2"瞎了没人知道"在最常见配置下延迟 5h。修法：阈值改时间基（noSuccessMs）或默认值对齐节拍，同步两处文案。

**2. verify-rotate 三件事**：a) 当前 0 收益（20 份 CLOSE-GATE 全在 7 天内，dry-run 实测）；b) 覆盖面 304K/1.5M≈20%——per-todo 日志（1.2MB 大头，如 PS1-4/HE1 各 203 行）不在策略内；c) 无自动化接线（package.json 手动脚本，CI/close 都不调）——不接线则 `.ai/verify` 继续只增不减。另注意 git 历史仍永久保留被截前的 blob，轮转只省工作区。

### 仅记录

3. **rounds-history 仍是本地文件**：fresh clone/本地账丢失即重置轮次，maxRounds 的"越修越坏截停"仍可被 re-clone 绕过——修复解决的是"关账清零"路径，不是"本地性"（挂认领 ref 或远端账是后续方向）。
4. **headless 执行腿（T5）接通时的身份回路未建**：目标仓 `.ai/tasks/` 下由 headless 执行器提交的任务，若执行器未注入 GIT_AUTHOR_*，将全部被新判据拦在 close。当前 headless 未启用，属潜伏面。
5. markHealth 的 osascript 通知在测试期会真弹（5w 设 ticks=2，macOS 上每次 gate 运行弹通知）；Linux CI 无 osascript，spawnSync 不抛，无影响。
6. release()（布尔）与 releaseEx() 双 API 并存；剩余 3 处布尔调用点（:276 releaseAll、:700 feishu_ack_failed、:870 task_failed）均无"失败删本地账"语义，无 D11 形态，可择机收敛。
7. 上次体检 P2/P3 其余项本批未动，仍挂账：C1 轮询 O(N) 串行+per_page=100 正确性崖、gate 线性肥大（~115s）、broker 冻结族。task-loop 套件断言 132→128 系 51b7919 删死码测试段所致，非遗漏。
