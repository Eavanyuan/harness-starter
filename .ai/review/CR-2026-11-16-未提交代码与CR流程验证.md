## 二、Coding Agent CR 流程验证（独立审阅者，全文 /tmp/agent-cr-flow-audit.md）

### 核心判定

**当前流程下，coding agent 修完 bug 可以不经过任何 CR 直接 push 并开 MR。缺口三层叠加：**

```
coder: 载技能→编码→补测试→verify→审计四项 ⇒ 退出（⚠ 无 CR/自审指令）
  │
orchestrator: impl→review(自报 gate)→ci→done（⚠ push/MR 与 state.stage 无绑定）
  ▼
git push ── guard_command 只拦高危，普通 push 放行 ──▶ 开 MR（无拦截）
  ▼
本仓库 CI: doctor+测试+ci-verify（不查 CR 记录）→ 绿
  ▼
broker: 发飞书卡片（不执行审核）
═══ CR 实际发生点（全部在 MR 之后/之外）═══
MR 人审 ｜ code-reviewer agent（"MR 创建后使用"）｜ /cr 手动 ｜ 目标仓 CI 接 ai-review（仅示例）
```

### 缺口分层

| 层 | 缺什么 | 证据 |
|---|---|---|
| **prompt** | coder.agent.md 全文无提交前 CR/自审指令；orchestrator review 门禁自报（gate_result 手填，verify.mjs:798 明说"机器判不了"） | M1 |
| **hook** | guard_command 只拦 force push 等高危；普通 push / MR 创建零拦截、零 CR 前置校验 | M2 |
| **CI** | quality-gate.yml 不执行 ai-review cr、不查 CR 记录存在性；ci-verify 对未评估门禁只提示不判红 | M2 |

### 附加发现

| # | 问题 | 严重度 |
|---|---|---|
| M3 | `ai-review --type cr --machine-only` 空壳通过：cr 的 machine_checks=[]，0 检查产出 exit 0"通过"——会喂饱任何"verdict 存在且 red=0"校验 | 必须修 |
| C1 | 目录不一致：code-reviewer 写 `.ai/review/`、ai-review 写 `.ai/reviews/`——事后按路径回溯会漏 | 值得考虑 |
| C2 | orchestrator 只泛写"调度对应子 agent"，未写明 review 阶段调度谁——CR 触发完全靠会话自觉 | 值得考虑 |

### ai-review.mjs 本地可跑

有 `--base` 参数（`node scripts/ai-review.mjs --type cr --base HEAD~1`），可在本地执行不依赖 CI——但需配 `AI_REVIEW_API_KEY`（无凭据 fail-closed exit 2）或修 M3 后用 `--machine-only`（当前空壳）。

## 三、修复方向（建议，待你决策优先级）

1. **coder.agent.md 加退出条件**：`.ai/reviews/cr-*.md` 存在且 red=0（或记名 waive），否则不许 push——最便宜的一层
2. **guard_command 对 git push 加前置校验**：本任务 stage≥review 或 cr verdict 在（比 1 更硬，hook 层强制）
3. **修 M3**：machine_checks 为空的类型禁用 --machine-only（防空壳绿灯喂饱 1/2）
4. **统一目录**：`.ai/review/` 与 `.ai/reviews/` 二选一（C1）
5. **orchestrator 明写**：review 阶段调度 code-reviewer 子 agent（C2）
