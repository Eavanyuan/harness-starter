# 修 bug 标准动线（信息不全追问版）

> 前提：task-loop 拉到飞书 bug → 认领 → 接单（状态流转 Processing）
> 你（修复 agent/人）接手时按以下步骤走。**先复现，后修复——复现不了就不修。**

## 第一步：读单 + 评估信息

```
get_workitem_brief → description + create_by + 附件
```

三项判据（信息够不够**着手尝试**复现）：
- 有截图（界面问题看得到实际状态）
- 有日志/堆栈（后端问题看得到错误）
- 描述里有操作路径（能照着做）

**三项全无** → 不要往下走，调 `checkInfoOrAsk` 追问 @提交者，然后停。

## 第二步：尝试本地复现（核心步骤——真的动手）

根据描述在本地实际操作：

- **界面 bug**：起前端 + 后端，照描述操作，看能不能触发
- **后端 bug**：写一个测试用例触发描述的代码路径，看错误是否出现
- **数据 bug**：构造描述的数据场景，验证行为

```bash
# 典型复现验证（tda-server）
cd ../TDasset && mvn -pl tda-server test -DskipTests=false -Dskip.tests=false -Dtest=<复现测试>
```

**复现成功**（错误出现了）→ 写红灯日志（verify-run 包装失败的复现测试），继续第三步修复。

**复现失败**（错误没出现）→ **不要修**，执行追问：

```javascript
// 调 feishu-ask 的追问（说明你试了什么、为什么复现不了）
checkInfoOrAsk({ call, projectKey, workItemId, workItemType: 'Defect' })
```

追问评论模板（自动带 @提交者）：
> [自动追问] @提交者 我按描述在本地尝试复现但未能触发错误：
> - 尝试了：（具体描述你做了什么——起服务/写测试/构造数据）
> - 环境：（版本/配置）
> - 结果：（预期的错误未出现）
> 
> 请提供：截图 / 日志文件 / 更详细的操作步骤（精确到页面和按钮）。
> 补充后我会重新尝试。

追问后**停在这个 bug**，继续处理下一张（不要占着锁等回复——认领释放，等下一轮轮询重新拉到时信息可能已补齐）。

## 第三步：复现成功 → 修复

1. 红灯日志（复现测试失败运行）
2. 修复代码
3. 绿灯验证
4. `verify-run` 落证据

## 什么算"复现失败"

| 情况 | 处理 |
|---|---|
| 照描述操作，错误没出现 | 复现失败 → 追问 |
| 代码路径里找不到描述的功能/页面 | 可能版本不对/功能不存在 → 追问 |
| 测试写了但断言过不了（预期行为=实际行为） | bug 可能已修 → 追问确认 |
| 环境起不来/依赖缺 | **不算复现失败**——修环境后再试 |
