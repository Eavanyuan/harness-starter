# RS-harness 文档完备性与阶段链

> 产出：requirement-analyst 角色 · 落到 `docs/01-requirements/`
> 规则：业务取舍留白，技术方案不进 RS。

## 1 背景与痛点

harness 门禁能回答"这一阶段跑过评估没有"，回答不了"这份文档够不够让下一个人接着干"。
首版 FS/RS 评审时，审核人面对 300 行新文档没有抓手，只能凭印象点批准——定稿看起来发生了，
缺的章节、只剩表头的空表、没落到 FS 的 RS 条目照样缺。

现状的代价有三笔：

1. **假完备**：模板原样留着、表格只留表头，格式上"有这一节"，内容上一个字没有；
2. **双向失联**：FS 写了 §4.x 却没任务去做（漏做，交付前一周才发现）；WBS 的任务指向
   已被改掉的 FS 小节（悬空任务，做出来没人要）。两个方向都只有等出事才被发现；
3. **次序错**：WBS 曾排在 FS 评审之前。拆叶子的验收标准只能来自已评审的 FS，先拆等于在
   想象上判断；FS 补齐后 WBS 往往不回头，上面两个方向的失联就都补不回来了。

另有一类更隐蔽的代价：判据本身有洞，但洞的表现是"绿灯"。中文/空格文件名被当成"一句说明"
跳过，被跳过的文档从来没被打开过，结论却是"完备性通过"。

## 2 用户故事

### US-1 首版评审能看到缺什么

- **作为**：规格审核人
- **我希望**：打开评审包就能看到"哪份文档缺哪一节、哪条 RS 没落到 FS"
- **以便**：按清单要补齐，而不是通读 300 行后凭印象签字

**验收标准**

- Given 一份 FS 的 §9 只有表头没有数据行 When 跑完备性检查 Then 判红并点名"测试要点有空章节"
- Given 一份 RS 的 US-2 没出现在 FS 追溯表里 When 跑完备性检查 Then 判红并点名 US-2 未被覆盖
- Given 三份文档齐备且非空 When 跑完备性检查 Then 放行，且不产生任何告警

### US-2 阶段次序不许把判断建在想象上

- **作为**：流程维护者
- **我希望**：WBS 拆解只发生在 FS 评审之后
- **以便**：每条叶子的验收标准都能指回一处已评审的行为定义

**验收标准**

- Given 现行阶段链 When 读取链定义 Then 次序为 rs、adr、fs_review、wbs、impl
- Given 一个任务的 stage 写成 fs-review（连字符） When 跑状态校验 Then 判红并列出合法阶段名

### US-3 判据变更不许把合规的历史判红

- **作为**：已有任务的使用者
- **我希望**：链序调整后，我按旧次序记下的 stage_history 仍然被认作合规
- **以便**：我不必为了过门禁去改历史，也不必把跳阶检查关掉

**验收标准**

- Given 一段按旧链记的 history（rs、wbs、adr、fs_review、impl）When 用新链校验 Then 放行
- Given 一段在两个链上都不相邻的 history（fs_review 之后回到 adr）When 校验 Then 判红且要求记名

### US-4 产物登记必须能被打开

- **作为**：门禁维护者
- **我希望**：artifacts 里登记的路径一定能被读到，中文与空格文件名不受歧视
- **以便**：不会出现"检查通过"却没有一个字节被检查过的情况

**验收标准**

- Given 登记 `docs/需求 规格.md` 且文件存在 When 跑完备性检查 Then 放行
- Given 登记 `docs/需求 规格-不存在.md` When 跑完备性检查 Then 判红并点名该路径
- Given 登记写成一句说明（读不出路径）When 跑完备性检查 Then 判红并说明"等于没登记"

## 3 核心需求

| 编号 | 需求 | 优先级 | 来源 |
|---|---|---|---|
| R-1 | 模板占位符残留可判 | P0 | US-1 |
| R-2 | 模板章节齐全且非空（只有表头算空） | P0 | US-1 |
| R-3 | RS 每个故事至少两条可观测验收标准 | P1 | US-1 |
| R-4 | FS 追溯表覆盖全部 RS 条目 | P0 | US-1 |
| R-5 | WBS 与 FS 小节双向覆盖（悬空任务与漏做都判红） | P0 | US-1 |
| R-6 | 阶段链单源、次序为 rs 到 adr 到 fs_review 到 wbs 到 impl | P0 | US-2 |
| R-7 | 退休链序继续被认作合规 | P0 | US-3 |
| R-8 | artifacts 登记必须是可解析路径 | P0 | US-4 |

## 4 非功能约束

| 类别 | 约束 | 判据 |
|---|---|---|
| 边界 | 只在越过产出阶段之后判 | 停在 rs 或 fs_review 阶段的任务不因文档未完成判红 |
| 权限 | 判据库不自己保存阶段链 | 链由调用方注入，两处定义即视为缺陷 |
| 兼容 | 存量 state 不迁移也能过 | 只补校验视图，不改写磁盘内容 |
| 性能 | 一次完备性检查不读全仓 | 只读 artifacts 声明的三份文档与 templates |
| 数据量 | 文档规模按百行计 | 单份 500 行以内不产生明显延迟 |

## 5 范围外

- 不做内容质量判断（方案好不好、措辞是否清楚）——那要读语义，归人审与 SR 报告
- 不检查 ADR 是否齐全（ADR 的完整性由 adr 阶段门禁与人审负责）
- 不为未声明的产物补检查：不登记就检不到，这件事只提示不判死
- 不改写任何 state 落盘内容：迁移只产出校验视图

## 6 术语表

| 术语 | 含义 | 易混淆点 |
|---|---|---|
| 产出阶段 | 产出某份文档的阶段（RS 为 rs、FS 为 fs_review、WBS 为 wbs） | 与"当前阶段"不是一回事 |
| 假完备 | 格式上有这一节、内容上一行没有 | 与"内容写错了"不是一回事 |
| 悬空任务 | spec_ref 指向不存在的 FS 小节 | 与"FS 有小节没任务"（漏做）方向相反 |
| 退休链 | 曾经当过正式阶段次序、已被调整掉的链 | 不是"任何顺序都放行"的开关 |

## 7 开放问题

| # | 问题 | 候选解读 | 影响 | 是否业务取舍 |
|---|---|---|---|---|
| Q1 | 未声明产物是否判红 | 判红 / 只提示 | 判红会逼人删声明，只提示则覆盖不到 | 是 |
| Q2 | 退休链保留多久 | 永久 / 下个大版本清空 | 清空会让老任务突然变红 | 是 |
