# FS-harness 文档完备性与阶段链

> 产出：spec-writer 角色 · 落到 `docs/02-features/harness/`
> 规则：逐节非空；代码片段引用真实路径；契约先行。

## 1 概述

给 harness 补一条"文档写全了没有"的机器判据，并修正阶段链把 WBS 排在 FS 评审之前的次序错误。
使用者是规格审核人与 orchestrator：前者靠它拿到"缺什么"的清单，后者靠它决定能不能推进阶段。
关联 RS 的 US-1、US-2、US-3、US-4。

## 2 需求追溯

| RS 条目 | 本文档小节 | 覆盖状态 |
|---|---|---|
| US-1 | §4.1、§4.2、§4.3 | 完整 |
| US-2 | §4.4 | 完整 |
| US-3 | §4.4 | 完整 |
| US-4 | §4.5 | 完整 |

## 3 方案要点

- 关联 ADR：本变更无多方案技术决策点，不单独立 ADR（记名豁免见 WBS 收口说明）
- 关键取舍：判据只收"文档内部客观事实"，语义质量留给 SR 报告与人审

## 4 详细设计

### 4.1 占位符与空章节

- 输入：`state.artifacts` 声明的文档路径 + `templates/` 下的同名模板
- 处理：占位符集合从模板反推（模板里所有尖括号片段，先剥围栏代码、行内代码、引用块与
  HTML 注释）；文档正文按同样规则剥一遍后逐个比对。章节按二级标题切分，标题去掉序号后比对；
  章节"空"的判定是"没有正文行且表格没有数据行"——只有表头的表格算空。
- 输出：`[{id, rule, reason}]`，与 TODO 校验同形状，供 hook 与 CI 共用
- 失败分支：模板读不到时跳过该文档的章节判据（不猜测模板内容），占位符集合为空时同理

### 4.2 追溯与覆盖率

- 输入：RS 正文（`### US-n` 小节）、FS 的"需求追溯"章节表格
- 处理：从 RS 抽出全部 US 编号；从追溯表抽出每行的 US 编号与最后一列状态。RS 里有、表里
  没有的判"覆盖率不足"；状态列命中"部分 / 未覆盖 / 否 / —"的判"标称部分覆盖"。
- 输出：两类失败各一条，点名具体 US 编号
- 失败分支：追溯章节缺失或读不到表格时，单独报一条"读不到追溯表"，不再逐条报覆盖率

### 4.3 WBS 与 FS 双向覆盖

- 输入：WBS 的"拆分树"表格、FS 的三四级数字标题（如 4.1）
- 处理：先判必需列（id / 任务 / 验收标准 / spec_ref / depends_on），缺列就停在这一层，
  避免"一处缺列变二十条噪音"；再逐行判验收标准非空、spec_ref 形如 `fs#§4.2@<blob7>`、
  depends_on 指向存在的 id；最后做双向比对：spec_ref 的小节必须存在（否则悬空任务），
  FS 的每个四级小节必须有任务指向（否则漏做）。
- 输出：每条失败点名具体 id 或小节号
- 失败分支：spec_ref 前 24 字回显，让人能看出自己写成了什么

### 4.4 阶段链与退休链

- 输入：`state.stage`、`state.stage_history`
- 处理：链定义单源在 `hooks/lib/verify.mjs`（`STAGE_CHAIN`），次序为 rs、adr、fs_review、
  wbs、impl、review、ci、retro、done。相邻判定先看现行链的前进方向；不相邻时再比对
  `RETIRED_STAGE_CHAINS` 里登记过的旧链（v1 为 rs、wbs、adr、fs_review、impl…）。
  两条链都不相邻才算跳阶，跳阶要求该条 history 有 `waived_by`。
- 输出：阶段名非法、档位非法、跳阶未记名三类失败
- 失败分支：退休链只认前进方向，逆序（如 fs_review 之后回到 adr）照样判红

### 4.5 产物路径解析

- 输入：`state.artifacts` 的字符串值
- 处理：去掉首尾引号与反引号后，从字符串开头非贪婪匹配到第一个文档后缀（md / markdown /
  mdx / txt）。允许路径里带空格与中文——它们都是合法文件名字符；路径末尾再写一句说明不影响
  解析。解析不出路径的值（如"见飞书文档"）判红，而不是静默放过。
- 输出：解析成功的路径继续参与存在性检查与内容检查；失败的单列一条"读不出文件路径"
- 失败分支：文件不存在报"声明与事实不符"，并给出两条出路（落盘或改成 null）

## 5 接口契约

| 方法 | 路径 | 入参 | 出参 | 错误码 |
|---|---|---|---|---|
| 函数 | hooks/lib/doc_completeness.mjs 的 checkCompleteness | state、repo、stageChain | 失败数组 | 不适用 |
| 函数 | hooks/lib/doc_completeness.mjs 的 declaredFile | 声明值字符串 | 路径或 null | 不适用 |
| CLI | node scripts/ci-verify.mjs | --local、--file | 退出码 0 或 1 | 1 表示门禁未通过 |

## 6 数据变更

| 变更 | 类型 | 迁移脚本 | down 脚本 | 破坏性 |
|---|---|---|---|---|
| 无 schema 字段变更 | — | 不适用 | 不适用 | 否 |

## 7 交互与状态

- 状态矩阵：ui_scope 为 NONE，不适用
- 关键交互：`npm run verify:state` 全量扫描；`harness-cli review-packet` 按需生成评审包，
  有机器可判的待补项时退出 1

## 8 配置项

| key | 默认值 | 说明 | 是否必填 |
|---|---|---|---|
| gates.requireVerifyLog | true | 是否要求 TODO 完成后有 verify 日志 | 否 |
| gates.verifyFreshnessHours | 72 | 本地口径下证据时效（小时） | 否 |

## 9 测试要点

| 场景 | 断言 | 边界 |
|---|---|---|
| 三份文档齐备 | 退出码 0，无告警 | 文档含中文与空格文件名 |
| 占位符残留 | 退出码 1，点名占位符 | 围栏代码里的尖括号不算 |
| 章节只有表头 | 退出码 1，点名章节 | 引用块不算正文 |
| 中文路径指向不存在的文件 | 退出码 1，回显该路径 | 路径末尾带说明 |
| 旧链 history | 退出码 0 | 逆序仍判红 |

## 10 兼容与回滚

- 旧数据怎么办：存量 state 不改写；旧链 history 由退休链登记表认出
- 旧客户端怎么办：`declaredFile` 对纯路径的行为与旧版一致，只有"读不出路径"从放行改为判红
- 出问题怎么回滚：回退 hooks/lib/doc_completeness.mjs 与 hooks/lib/verify.mjs 两处即可，
  判据库与链定义都不写盘
